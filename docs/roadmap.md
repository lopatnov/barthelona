# Roadmap

Phased plan for barthelona. Each phase has a goal, deliverables and exit criteria. A phase is done only when its exit criteria are met; the benchmark decides whether optional subsystems are switched on.
Every phase's exit criteria also include the phase review (D-037): it ran, and its blocking issues are fixed.
Architecture: `docs/architecture.md`. Decisions: `docs/adr/`.
Diagrams of the finished system, with what exists today marked: [`docs/roadmap-diagrams.md`](roadmap-diagrams.md). Update a diagram in the same PR that delivers its box.

Current status (2026-10-14): **Phase 0 in progress** — repository and environment done (design, agent configuration for Claude Code and Codex, conda scripts, hash-locked dependencies, baseline tests); code skeleton started: domain models, the `var/app.sqlite` store and the `python -m barthelona` entry point exist; the toolchain probe and `verify` are next.

## Phase 0 — Foundations and the deterministic spine (about 1–2 weeks, no agent loop yet)

**Goal:** prove the toolchain, the generators and the verification oracles without any LLM, and choose the local model on measured numbers.

**Deliverables**
- Repository: `AGENTS.md` / `CLAUDE.md`, `.claude/` config and the Codex mirror ✔, `.gitattributes` ✔, `pyproject.toml` ✔, `environment.yml` ✔, hash-locked requirements ✔, `create_env` / `activate` / `lock` scripts ✔, `doctor.ps1` ✔, dependency fingerprint + baseline tests ✔.
- Code skeleton: domain models (Pydantic v2) ✔; persistence (SQLite WAL schema and migrations for `runs`, `commands`, `events`, `gates`, `llm_calls`) ✔; `python -m barthelona` CLI (entry point with `version` and `schema` ✔; `verify` and `probe` land with their deliverables).
- Training data (D-036): `TrainingSample` model, the off-by-default setting, the local dataset writer and reader with secret redaction, `python -m barthelona training status` ✔.
- Environment fixes (owner actions): `.wslconfig` memory cap; Qdrant storage moved to a named volume (see `docs/runbook.md`).
- Execution: Docker images `bart-tc` (`docker/toolchain`) and `bart-run` (`docker/runner`) with a CI smoke test (`scripts/docker-smoke.sh`) ✔ (base `ubuntu:26.04` by tag; digest pinning comes with `barthelona probe`, which has to run on the PC where the images are built, so `config/toolchains.lock.json` is still unwritten); the WSL agent (JSON lines, staging, allowlist, path fence); `barthelona probe` writing `config/toolchains.lock.json`.
- Assemblers: NASM and GAS (Intel and AT&T) dialect adapters; ld/gcc linkers; diagnostics parsers with real captured fixtures.
- Codegen: contract registry → `.inc` files, stubs, `contracts.h`, C harness, Makefile, with golden tests.
- CI/CD templates for produced projects (D-048, #126): `barthelona.scaffold.render_ci` renders `ci.yml` (verify ladder in the sandbox), `release.yml` (tag build, checksum, publish) and `dependabot.yml` for `linux-x64` NASM/GAS, tested and actionlint-checked in barthelona's CI ✔; the scaffold step that writes them lands with the engine (Phase 1).
- Verification: ladder levels V0, V1, V2, V5, V6 plus the tamper gate; first ABI mutation corpus entries ✔ (8 kinds, NASM and GAS Intel, assemble-only; `tests/abi_mutation/`); `barthelona verify`.
- Models: minimal gateway (OpenAI-compatible backend + FakeGateway) ✔ (`llm/`: catalog loader, role router with fall-through, streaming `OpenAIChatBackend` for local servers, `strip_think`; cloud backends, breakers, retries and the ledger stay in Phase 1, #108); the strict FILE envelope parser (`prompting/`, #111) ✔; bake-off harness (10 single-prompt tasks per candidate: tok/s, JSON-schema validity, pass@1; #113: `bench/` library, 10 integer-only dev tasks, fix-loop runner and paired statistics ✔, CLI, the gcc arm and the run on the PC still open). **Run the bake-off and a bounded end-to-end spike (generate, assemble, test, fix) early in this phase, not last** (plan review, 2026-10-17, #100). Arms: single prompt; the **strong baseline** (single prompt plus up to N fix iterations fed with assembler and test output); a C-then-`gcc -O2 -S` arm (measurement only, no node; D-040); informational: a general coding agent driving `barthelona verify`.
- Tooling: a stable `barthelona verify --json` output, so the oracles are usable without the engine ✔ (one JSON document `{status, levels}` on stdout, progress on stderr, exit code as in text mode).

**Exit criteria**
- Two hand-written 3-module projects (one NASM, one GAS) pass V0–V2, V5 and V6 through `barthelona verify`.
- An all-stub skeleton generated from a sample `contracts.yaml` builds ✔ (`tests/unit/verification/test_skeleton.py`, docker job).
- Parser and codegen tests are green.
- A bake-off table exists; one main local model is chosen and loaded in LM Studio at 16K context.
- The single-prompt and strong-baseline scores are recorded with their run-to-run noise (3 seeds or more, paired by task; #101).
- The phase review (D-037) ran, and its blocking issues are fixed.

## Phase 1 — MVP vertical slice (about 3–4 weeks)

**Goal:** an end-to-end Meta-Agentic Scrum run from the Streamlit UI, from request to merged repo, on the linux-x64 NASM/GAS presets.

**Delivery order (architecture review, 2026-10-17, issue #69):** slice **1a, walking skeleton** first: L0 templates only, one OpenAI-compatible backend plus `FakeGateway`, envelope parser, context assembler, ladder and tamper gate, outer run graph with G1/G2/G4, worker and event log, UI pages New request, Approvals and Live run, and the crash spike on that graph. Slice **1b, breadth** follows: validator T1-T10, `compile`, L1, re-planning, the other providers, breakers and caps, the training-data hook, remaining pages. The exit criteria below apply to the end of 1b; 1a ends with one 3-module NASM program from a request and the single-prompt baseline vs. L0 recorded. Also in 1a (D-049): the catalog loader with `endpoints[]` (F-13, #25, F-7) and a Linux-host CI job that runs the walking skeleton with `FakeGateway`; in 1b: least-loaded scheduling with affinity across endpoints on several PCs (D-047, #44).

**Deliverables**
- Engine: outer run graph (create mode, and edit mode for barthelona-created workspaces); gates G0, G1, G2, G4, G5 (G3 auto when green); node registry; `compose`; validator T1–T10 with Hypothesis property tests; `compile`; topology persistence and revisions.
- Sprint composition: L0 rule planner, plus **L1 via `planner.composition_level: L1`** (experimental, D-028); multi-unit `LoopBound`s; stall detector; bounded re-planning.
- Policy v1: templates `module_create`, `symbol_patch`, `fix_build`, a minimal `contract_change`, `integration`; role prompts. The minimality gate ships here too, for barthelona-created projects (symbol spans come from `contracts.yaml`), so edit-mode pipelines satisfy T6.
- Prompting: envelope parser (FILE / SEARCH-REPLACE / SYMBOL); context assembler with token budgets.
- Scaffold outputs for a new project (F-68, F-69; #126, #127): the `header_gen` node writes the CI/CD workflows from D-048 and the other standard repo files (`LICENSE` chosen on the New request page, `.gitignore`, README build/run/test/release sections, `SECURITY.md` stub) once at project creation.
- Model gateway: backends for LM Studio/Ollama (OpenAI-compatible), Anthropic, OpenAI, Gemini and DeepSeek; `config/models.yaml` catalog; per-call ledger; optional caps; error taxonomy, retries, circuit breakers and fallback chains ending in the local model (D-029, D-030).
- Training data (D-036): the engine records each code-producing attempt after the ladder when `Run.collect_training_data` is set, passing the gateway's key values to the redactor and refusing runs on `bench/tasks/holdout` tasks (unit test); the New request checkbox; `barthelona training export` (supervised pairs from accepted attempts, preference pairs from `improves_on_seq`; local-model samples only unless the owner opts in per provider).
- Run control: budgets, `StopReason`, escalation E0, E1, E3, E4; branch per run, commit per green task, tag per increment.
- Knowledge: `facts.sqlite` (NASM App. F, directive indexes, `syscall_64.tbl`, SysV ABI row); FTS5 docs; rule cards for nasm / gas-intel / gas-att on linux-x64.
- Process: `scripts/run.ps1` (worker + Streamlit); worker with event log + JSONL mirror; Streamlit pages New request, Approvals, Sprint board (topology DOT), Live run, Review, Toolchains & models (with provider health), Runs.
- Benchmark v1: 12 create + 8 edit tasks (dev + holdout); cassette replay.
- Crash/resume spike, with crash points after the effect, after the event, mid-batch and during a gate (D-044).

**Exit criteria**
- Crash/resume spike passes (kill mid-task and during a gate; no finished node re-runs), or the interpreter fallback is adopted and passes the same test.
- Graph tests green with FakeGateway: happy path, fix loop, stall, re-plan, escalation, refusal, provider failover, budget stop, tamper rejection.
- Dev-split bench: the hybrid profile beats the **strong baseline** (single prompt plus fix iterations, not the bare single prompt) by a margin set in Phase 0 from the measured noise, with paired intervals that exclude zero (#101); local-only recorded; zero tamper escapes; L0 vs L1 recorded. A margin smaller than the bench size can detect is not a gate: grow the task set first.
- The owner creates a 3-module NASM program from a Russian-language request through the UI and approves it at the gates.
- Stance until Phase 2: increments are accepted on the MVP DoD (V0–V2 + V5/V6) and labelled **ABI-unverified** in the UI and the increment record, until the V3/V4 oracles and the mutation corpus are in place.
- The phase review (D-037) ran, and its blocking issues are fixed.

## Phase 2 — Stronger oracles and full meta-agency

**Goal:** stronger verification, plus the complete Meta-Agentic layer.

**Deliverables**
- V3 Capstone static ABI lint; the callee-saved canary trampoline in the V5 harness (F-56); V4 Unicorn ABI checker (canaries, alignment, red zone, DF, syscall allow-list, registry mocks, DWARF mapping; AVX routed to V5) **only for the mutation-corpus kinds that V3 plus the V5 canary cannot detect** (#102); full ABI mutation corpus.
- Reference-implementation differential tests (C reference, random inputs through the generated harness) in the Definition of Done (#102).
- Policy v2: templates `candidates` (E2) and the `trace_capture` slot (V7).
- A local MCP server exposing the toolchain and verification tools (moved from Phase 5, plan review #100): the oracles stay useful to general coding agents even if the engine does not beat the baseline.

**Phase 2 has two tracks that must not block each other** (plan review, 2026-10-17): **2a** is the oracle work above, **2b** the meta-agency below. 2b starts only after the L0 bench shows a failure class that graph composition could plausibly fix.

**2b deliverables**
- **L1 on by default** if the paired bench shows no regression; **L2** (AI composes whole pipelines from node types) behind a flag for strong tiers.
- Retrospective report and overlay changes with revert in the UI; lesson candidates stored, not yet injected.
- _(experimental, gated by bench)_ `compile_high_level` node type: LLM generates C,
  `gcc -O2 -S` inside `bart-tc` produces the `.s` patch; GAS presets first; enabled only
  if its paired gain over direct codegen on the Phase 2 holdout split excludes zero at the bench size (D-040, #34, #101). The Phase 0 bake-off arm gives the first data.

**Exit criteria**
- 2a: mutation corpus: 100% of bad cases detected, 0 false positives.
- 2b: every AI-composed topology either validates or falls back to L0; no run is blocked.
- Bench: Phase 2 ≥ Phase 1 on dev and holdout; L2 enabled for a profile only if it beats L1 there with a paired interval that excludes zero. Results recorded in an ADR.
- The phase review (D-037) ran, and its blocking issues are fixed.

## Phase 3 — Edit mode for external projects, memory, optional vector search

**Deliverables:** importer and target detection; baseline build with `fix_build`; repo map (regex extractors + PageRank); inferred contracts (nm + Capstone); characterization tests; localizer; minimality gate extended to external projects (symbol spans from the repo map); full `contract_change` flow; lessons lifecycle with regression checks and an inbox; retrieval eval (≥60 queries); Qdrant hybrid backend behind the Retriever interface; MASM docs from cpp-docs.

**Exit criteria:** external seed repos edited with zero characterization regressions; Qdrant on by default only if recall@5 beats FTS5 by the agreed margin; lesson injection on only if the bench improves; the phase review (D-037) ran, and its blocking issues are fixed.

## Phase 4 — Dialect and target breadth

**Deliverables:** FASM 1 (ELF64, PE64; frame-based diagnostics; `-s` line mapping; `public`/`extrn` headers); optional fasmg/fasm2; Win64 targets (NASM/GAS + mingw, wine runner, shadow-space and `.pdata` checks); ELF32 cdecl; asmc/UASM for MASM syntax; ml64 opt-in on Windows (VS Build Tools, admin); boot-sector preset with qemu-system. Each preset ships a rule card, a conformance kit, bench tasks and a CI/CD template family (D-048, F-68).

**Exit criteria:** each preset passes its conformance kit and solves at least 5 bench tasks within budget; the phase review (D-037) ran, and its blocking issues are fixed.

## Phase 5 — Policy Lab, gated research, extras

**Deliverables:** Policy Lab (PolicyPatch → candidate version → A/B on holdout, ≥3 repeats, batch APIs → G6 activation/rollback); gated web research (approval, domain allowlist, low-trust candidates promoted only after a fix passes); optional advisory critic on a different model; OpenTelemetry → Phoenix; OpenVINO Model Server trial; AArch64/RISC-V via qemu-user; KolibriOS if chosen. (The local MCP server moved to Phase 2a.)

**Exit criteria:** at least one policy patch activated with a measured holdout gain; a rollback exercised; web-sourced knowledge never reaches prompts without the evidence step; the phase review (D-037) ran, and its blocking issues are fixed.

## Phase 6 — More target families: C applications, then web and 2D (D-050)

**Goal:** build and verify software beyond assembly with the same loops, gates and ladder, so applications such as a JSON-configured reverse proxy with load balancer, a task scheduler or a 2D game become reachable. Starts when the Phase 1b exit criteria are met, in parallel with Phase 2; never before the assembler pipeline works end to end.

**Deliverables**
- Family abstraction: `family` axis on targets and contracts, registered checks and sandbox profile per family (D-046), CI templates per family (D-048).
- **C family:** gcc/clang adapters, warnings as errors, ASan/UBSan, unit and golden-I/O tests, a sandbox profile with loopback-only networking for server tests, a fake clock, rule cards, conformance kit, bench tasks. Proof projects: a CLI tool, a JSON-configured reverse proxy with load balancer, a task scheduler.
- Context assembler and repo map tested against a project of a few hundred functions.
- **Web and 2D family** (after C): Node tests in the sandbox, headless browser, replayable input scripts for 2D games, lint, accessibility, layout and contrast checks, screenshots at set sizes for a vision-model critique (advisory) and the human gate G4 for looks. Visual-feedback research (F-72) first.

**Exit criteria**
- C family: the three proof projects pass their ladder inside budget; at least 5 bench tasks per family solved.
- Web and 2D: a 2D game (Snake first) and a small web app pass their ladder, and the owner approves their look at G4.
- The phase review (D-037) ran, and its blocking issues are fixed.

## Phase 7 — Reference ambition: pure-assembly TLS 1.3 and HTTP/2 reverse proxy (D-054)

**Goal:** a reverse proxy for files and API requests with HTTP/2, with TLS 1.3 and its crypto written in assembly and no linked TLS or crypto library, built by Barthelona (mostly local models) in the network demo repo. This is the reference complexity for architecture reviews (owner, 2026-10-18), not a commitment to a date. Starts only after Phase 6 and a working multi-module edit mode.

**Deliverables:** the F-87 to F-94 items: module-DAG decomposition, spec ingestion with traceability, crypto vector and differential oracles, constant-time checks, loopback-only interop sandbox with conformance tools, fuzzing and memory-safety checks, disassembly aid (D-055).

**Exit criteria:** the proxy completes TLS 1.3 handshakes and serves HTTP/2 requests to `openssl s_client`, `curl --http2` and `h2spec` inside budget; all known-answer and differential crypto tests pass; the constant-time check passes on secret-handling code; fuzzing finds no unresolved crash; the demo README states that the result is an unaudited experiment; the phase review (D-037) ran.
